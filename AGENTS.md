# Better Song Search Quest

Android IL2CPP / Scotland2 mod, ID `BetterSongSearch`. Follow the parent
[workspace guidance](../AGENTS.md); this file covers BSS-specific entry points
and mistakes to avoid. Read target/toolchain versions from `qpm.json`,
`mod.template.json` and `CMakeLists.txt`, rather than copying historical versions.

## Where to work

| Change | Starting points |
| --- | --- |
| Startup, hooks, scene transitions | `src/main.cpp` |
| Search, cache and song-data lifetime | `include/DataHolder.hpp`, `src/DataHolder.cpp`, `src/Util/SongUtil.cpp` |
| Config, filters and presets | `include/PluginConfig.hpp`, `include/FilterOptions.hpp`, `src/FilterOptions.cpp` |
| UI | `src/UI/`, matching `include/UI/` declarations, `assets/*.bsml` |

- Keep `BSS_EXPORT_FUNC` on `setup` and `late_load`; other symbols are hidden.
- `setup` assigns `modInfo`. `late_load` initializes BSML/custom types, loads and
  validates config **before** starting the data-holder worker, installs hooks,
  then initializes the UI manager. Preserve that ordering.
- Follow existing `MAKE_HOOK_MATCH` / `INSTALL_HOOK(Logger, ...)` patterns and
  use `include/logging.hpp` for logging.
- Keep BSML bindings synchronized across declarations, implementations and markup.
  Edit `assets/`; `include/assets.hpp` is generated by `cmake/assets.cmake`.

## Config compatibility

- Use `getPluginConfig().Field.GetValue()` / `.SetValue(...)`. For batched writes,
  use `.SetValue(value, false)` followed by one `.Save()`.
- Keep filter persistence in `FilterProfile::LoadFromConfig()` / `SaveToConfig()`.
  Config and preset selections must be validated before indexing UI lists or
  preprocessing filters. Reset invalid values to defaults and persist config repairs.
- Reuse `ValidateSelection<Enum>` and reflectcpp enum membership checks; do not
  maintain hard-coded upper bounds. Sort mode is validated during config loading.
- Persisted enum IDs are compatibility data: append new options without shifting
  existing IDs, and keep dropdown order aligned with them. Requirement IDs are
  `Any=0`, `NoodleExtensions=1`, `MappingExtensions=2`, `Chroma=3`, `Cinema=4`,
  `None=5`, `Vivify=6`. `None` matches zero SongDetails mod flags.

## GC, callbacks and teardown

- Raw managed pointers, `UnityW`, native containers/globals, lambda captures and
  native coroutine frames do **not** root managed objects. Use explicit strong
  roots such as `safe_ptr<T*>` for managed references retained by native state,
  including across worker handoffs, scheduled callbacks and coroutine suspension.
- Rooting preserves the managed wrapper, not a destroyed native Unity object.
  Recheck Unity liveness when callbacks run; a non-null raw pointer is insufficient.
- Access Unity/HMUI on the main thread. Return worker results through
  `BSML::MainThreadScheduler::Schedule(...)`; rooting does not make UI access
  thread-safe.
- Give roots and callbacks an owner. At the end of that owner's lifetime, cancel
  work, invalidate stale callbacks, unsubscribe events and release roots/native
  state. A captured native `this` also needs a lifetime guarantee. Temporary view
  deactivation is not necessarily destruction: retain state intended for reopening.
- Never call virtual `Finalize()` from `DECLARE_DTOR`: it can recurse into itself.
  Avoid unnecessary custom finalizers and Unity API calls on the finalizer thread.

The workspace guide records the GC investigations behind these rules. For lifetime
changes, test reopening views, scene transitions and delayed callbacks on device;
source/build checks alone cannot establish GC safety.

## Dependencies

- Preserve `^x.y.z` dependency ranges in `qpm.json` and QMOD requirements.
  **Do not replace `^` with `=`** to match the local cache or resolved build.
- Let QPM manage `qpm.shared.json`. A concrete resolved version is not a dependency
  range; do not rewrite it into a range or manually pin generated requirements.
- Change dependency versions or target metadata only when the task requires it.
  Verify `extern/` wiring before assuming a sibling library checkout is used.

## Build, package and verify

Run from this repository's root:

| Task | Command |
| --- | --- |
| Restore dependencies | `qpm restore` |
| Debug build | `pwsh ./build.ps1` |
| Release build | `pwsh ./build.ps1 -release` |
| Release QMOD | `pwsh ./createqmod.ps1 BetterSongSearch -release` |
| Build, install, restart and log, when deployment is requested | `pwsh ./copy.ps1 -log -file` |
| Capture logs only | `pwsh ./start-logging.ps1` |

- Add `-clean` only when needed: it deletes `build/`, including diagnostics stored
  there. Preserve needed evidence first.
- `createqmod.ps1` builds, generates `mod.json` with `qpm qmod manifest`, validates
  its schema and creates `BetterSongSearch.qmod`. Manifest generation alone does
  not build or package. `qpm s qmod` uses the script's default debug build.
- Edit `mod.template.json` and QPM metadata, not generated `mod.json`. Keep
  `libBetterSongSearch.so` in `lateModFiles` and preserve the mod ID.
- Verify the QMOD opens, contains all manifest-listed files and no stale entries,
  and its library matches `build/libBetterSongSearch.so` by bytes or SHA-256.
  Check the intended package/game versions and dependency ranges. The script
  updates an existing archive, so removed payloads can otherwise linger.
- Report build/package checks separately from device validation. Packaging does
  not install the mod or demonstrate runtime behavior.
